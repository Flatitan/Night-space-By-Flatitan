# Night Space by Flatitan — сайт с регистрацией и личным чатом

Учебный стартовый проект: тёмный интерфейс, регистрация, вход, подтверждение email, профиль и личные сообщения. Фронтенд использует HTML/CSS/JavaScript, а Supabase — для аккаунтов, базы данных и Realtime.

## Что понадобится

- Компьютер.
- Интернет.
- Бесплатный аккаунт на [Supabase](https://supabase.com).
- Для запуска локального сайта — Python 3 **или** редактор VS Code с расширением Live Server.

## 1. Создай базу и систему аккаунтов

1. Открой https://supabase.com и создай аккаунт.
2. Нажми **New project**, укажи имя и пароль базы данных. Сохрани пароль базы в надёжном месте.
3. Когда проект будет готов, открой **SQL Editor** → **New query**.
4. Открой файл `supabase.sql` из этой папки, скопируй его содержимое в SQL Editor и нажми **Run**.
5. В Supabase открой **Project Settings → API** (или раздел **Connect**, в зависимости от интерфейса).
6. Скопируй **Project URL** и **anon/public key**. Ключ может называться `publishable key` в новом интерфейсе. Не используй `service_role` или `secret key` в браузере.

## 2. Подключи сайт к Supabase

Открой `app.js` в любом текстовом редакторе и найди строки в самом начале:

```js
const SUPABASE_URL = 'ВСТАВЬ_SUPABASE_PROJECT_URL';
const SUPABASE_ANON_KEY = 'ВСТАВЬ_SUPABASE_ANON_KEY';
```

Замени текст внутри кавычек на значения из настроек Supabase. Например, URL выглядит как `https://abcdefgh.supabase.co`. Не публикуй пароль базы данных или secret/service_role key.

## 3. Настрой подтверждение email

1. В Supabase открой **Authentication → URL Configuration**.
2. Для локального запуска добавь в **Redirect URLs** адрес `http://localhost:8000/**` (если поле принимает шаблоны) или `http://localhost:8000`.
3. Установи **Site URL** в `http://localhost:8000` для локального теста. Перед реальным запуском поменяй его на домен сайта.
4. В **Authentication → Providers → Email** проверь, что Email-провайдер включён и подтверждение email включено.
5. Если письма не приходят, проверь Spam/Junk. Для полноценного запуска настрой SMTP-провайдера в настройках Supabase: стандартная отправка писем может иметь ограничения.

После нажатия ссылки в письме пользователь вернётся на сайт. Затем он сможет войти со своим email и паролем.

## 4. Запусти сайт

### Вариант A — через Python

1. Распакуй архив.
2. Открой папку проекта в терминале/командной строке.
3. Запусти команду:

```bash
python -m http.server 8000
```

Если команда `python` не работает в Windows, попробуй:

```bash
py -m http.server 8000
```

4. Открой в браузере `http://localhost:8000`.

Важно: не открывай `index.html` двойным щелчком — модуль JavaScript может не загрузиться корректно без локального веб-сервера.

### Вариант B — VS Code

1. Установи Visual Studio Code.
2. Открой папку проекта.
3. Установи расширение **Live Server**.
4. Нажми правой кнопкой на `index.html` → **Open with Live Server**.
5. Добавь показанный Live Server адрес в **Redirect URLs** в Supabase. Для этого проекта удобнее закрепить порт 5500 и добавить `http://127.0.0.1:5500/**` и/или `http://localhost:5500/**`.

## 5. Проверь все функции

1. Зарегистрируйся с email, к которому у тебя есть доступ.
2. Открой письмо и подтверди адрес.
3. Войди в аккаунт.
4. Открой «Мой профиль», поменяй имя и сохрани.
5. Открой сайт в другом браузере или приватном окне и создай второй тестовый аккаунт.
6. Вернись в первый аккаунт: второй пользователь должен появиться в списке.
7. Отправь сообщение и проверь чат в обоих аккаунтах.

Чтобы тестировать чат, нужны **два разных аккаунта**.

## Что уже есть

- Адаптивный тёмный интерфейс.
- Регистрация и вход через Supabase Auth.
- Подтверждение email.
- Личный профиль и изменение отображаемого имени.
- Список зарегистрированных пользователей.
- Личные сообщения и обновление чата в реальном времени.
- Row Level Security (RLS) — пользователь читает только сообщения, где он отправитель или получатель.

## Важные ограничения прототипа

- Это стартовый проект, а не проверенный для крупного публичного запуска продукт.
- В этом примере email отображается в списке контактов других пользователей. Если это нежелательно, лучше убрать email из публичного списка и показывать его только владельцу аккаунта.
- Для публичного запуска нужны проверка безопасности, ограничения частоты запросов, защита от спама/абьюза, политика конфиденциальности, обработка жалоб и настройка SMTP.
- Не добавляй в клиентский JavaScript секретный `service_role` key. Публичный ключ допустимо использовать только вместе с правильно настроенными RLS-политиками.
- SQL включает создание таблиц и политик. Если в существующем проекте уже есть таблицы с такими именами, сначала проверь их схему и политики, чтобы не затронуть чужие данные.
